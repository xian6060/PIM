實驗說明

本實驗用來檢查 foreign free 在 alien cache 中累積後，閾值對執行時間的影響。

實驗目的

驗證目前已加入的 alien cache flush 門檻是否會影響整體執行效率。 由於 `freeUMalloc()` 在目前 thread cache 找不到對應區塊時，會把 pointer 放進對應 thread 的 alien buffer， 因此閾值大小可能改變 flush 的頻率與成本分佈。

foreign free alien cache threshold tuning host timing

實驗流程

1

Host 傳入 `mallocableRegionSize`、`pageSize`、`bufferSize` 與 `alienCacheFlushThreshold` 到 DPU。

2

DPU 建立 `uMalloc`、thread caches 與 alien caches，並執行測試配置。

3

依序量測 threshold = 1、8、16、32、64，每次都記錄 `dpu_launch()` 的執行時間。

4

比較不同 threshold 下的時間，找出較佳的 flush 頻率範圍。

結論

兩輪結果都顯示 alien cache flush 門檻會影響 DPU 執行時間，且在本次量測中以 32 表現最佳。

觀察

  • flush threshold 太低時，可能會增加 flush 次數，導致額外成本。
  • threshold 太高時，buffer 累積變多，成本不一定持續降低。
  • 在這組測試條件下，`32` 是最好的平衡點。

後續建議

  • 對每個 threshold 做多次重複量測，降低單次波動。
  • 若要更深入分析，可把 `device_enqueued_frees`、`device_flushed_pointers`、`device_flush_cycles` 加回計數器。
  • 把結果輸出成 CSV 再畫更完整的圖表也很適合。
